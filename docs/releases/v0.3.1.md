# PotatoCS / Odysseus Desktop v0.3.1 — Patch Release

## Summary

v0.3.1 is a narrow patch release following the v0.3.0 proof/hardening
release. It adds a degraded-backend UI for the one lifecycle path v0.3.0
left silent — sidecar recovery failure — plus a build-safety fix and
documentation added since v0.3.0. It adds no new product capability.

## What changed

- **Backend degraded-state UI** (`0721cfb6`, PR #5): when sidecar recovery
  fails, the app now shows a degraded-backend banner instead of failing
  silently.
  - A **Retry backend** action lets the user re-attempt sidecar recovery
    from the banner.
  - Sidecar loss during a **non-idempotent RPC** degrades without replaying
    the request (the v0.3.0 no-replay guarantee is preserved).
  - Successful recovery emits `degraded: false` and clears the banner.
  - Degraded/recovered event emission occurs after the state mutex guard is
    dropped, avoiding lock-held emission.
- **Build safety** (`458f7a8b`, PR #6): the v0.3.0 checksum record was moved
  out of the generated `dist/` directory so `npm run build:frontend` (which
  empties `dist/`) can no longer delete a tracked release checksum
  (issue #4).
- **Docs** (`4187b30a`, issue #2): README gained v0.3.0 download, checksum
  and verification instructions after the v0.3.0 release.

## What did not change

- No agents, bounded tool execution, deep research, memory, skills, blind
  compare or Cookbook features. No new vision backends, window-specific
  capture, or UI redesign. Privacy posture is unchanged.

## Validation

- Live degraded-UI smoke passed against the PR #5 implementation merged
  with main: forced recovery failure showed the banner, Retry recovered the
  backend, `degraded: false` cleared the banner, and non-idempotent RPC
  loss degraded without replay. See
  `projects/odysseus/V031_DEGRADED_UI_SMOKE_RESULT.md` (issue #1, closed).
