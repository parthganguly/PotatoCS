# PotatoCS / Odysseus Desktop v0.3.0 — Proof and Hardening

## Summary

PotatoCS is a local-first AI desktop project for ordinary computers. The
project ships its Windows app as Odysseus Desktop; v0.3.0 is a
**proof/hardening release**. It adds no agents, tools, research, memory,
skills or other new product capability. It hardens the sidecar lifecycle,
aligns all version sources, and ships with a recorded, commit-tied proof
bundle.

Naming: **PotatoCS** is the project; **Odysseus Desktop** is the shipped app
(`odysseus-desktop`, profile identifier `dev.odysseus.desktop`). Historical
public assets use the `PotatoCs` spelling; the canonical project spelling is
PotatoCS.

## What changed

- Sidecar graceful shutdown now has a bounded deadline; a hung shutdown
  reaches forced kill and child reap (`e9f36fbc`).
- The host detects forced sidecar death, restarts it, and retries a safe
  idempotent request at most once; non-idempotent requests are never
  replayed after sidecar loss (`bd635ea2`).
- A sidecar death during the startup `health.ping` no longer terminates the
  host; the host survives and auto-recovers (`7119e40c`), proved at source
  and installed levels.
- Lifecycle events are logged with fixed labels
  (`phase=exit/restart/retry`, `context=startup_health`) containing no RPC
  payload or private content.
- All version sources — `package.json`, `package-lock.json`,
  `src-tauri/Cargo.toml`, `Cargo.lock`, `tauri.conf.json` and the Python
  sidecar `__version__` — now report `0.3.0` (`5171fdf4`).
- One small pre-freeze answer-quality correction is included (`e1c8c774`,
  `fix: improve plain and visual answer quality`). It tunes existing
  plain-chat and visual answer behavior that shipped before the v0.3 proof
  freeze. It is not a new agent, tool, research, memory, skill,
  compare/Cookbook or redesign feature and does not expand v0.3.0 product
  scope.

## What did not change

- No agents, bounded tool execution, deep research, memory, skills, blind
  compare or Cookbook features. These remain not started.
- No new vision backends, window-specific capture, or UI redesign.
- Privacy posture is unchanged: local-first, trace privacy sanitization,
  strict progress identifiers and a test-time non-loopback egress guard.
  This is test/build-level proof, not an OS-level runtime firewall.

## Validation

At candidate `e8702c50` (and its no-source-drift predecessors recorded in
`projects/odysseus/`):

- Python suite: 297 passed, 0 failed, 0 skipped, with the autouse
  non-loopback egress guard active suite-wide.
- Frontend progress tests and production frontend build passed.
- Cargo check and cargo test passed (20 passed, 0 failed, 4 intentionally
  ignored helper-process fixtures).
- Installed-app lifecycle smoke passed two complete runs: clean install,
  normal close, relaunch, idle sidecar kill, sidecar kill during startup
  `health.ping`, recovery, and final no-orphan checks.

These checks validate the tested implementation and package. They do not
turn local-model output into a scientifically validated result.

## Known limitations

- The multimodal benchmark's committed real-route evidence remains
  skipped/unscored; benchmark plumbing is validated, model quality is not.
- Small local models can still hallucinate, miss evidence, or over-abstain.
- Window-specific screenshot capture is unsupported.
- The app remains internally named Odysseus Desktop in v0.3.0.
