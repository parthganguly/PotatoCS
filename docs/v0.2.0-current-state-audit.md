## Implemented v0.2.0 features observed

- App/runtime version sources have been moved to `0.2.0`.
- Image artifact storage exists under profile-managed originals, normalized images, thumbnails, crops, and captures.
- Image import validates supported formats, byte limits, decoded pixel limits, EXIF orientation, thumbnails, and normalized PNG derivatives.
- Image artifacts can be linked to messages through `message_artifacts`.
- OCR now has direct image OCR support in addition to document OCR.
- Model capability inspection uses Ollama `/api/show` and has a vision-capable model cache.
- Vision requests can send image bytes through Ollama `messages[].images` from normalized local images.
- Multimodal image eval storage and fixtures exist.
- Rust/Tauri capture and clipboard image import commands exist for full screen, region, and clipboard image paths. Window capture is explicitly unsupported.
- RAG metadata now carries artifact-derived provenance for indexed image text.

## Duplicated or dead paths

- Primary navigation still exposes `Chat | Documents | Images | Diagnostics`.
- The persistent document UI and image UI are separate instead of unified as Sources.
- Chat has an image-specific attachment toolbar instead of a universal composer attachment system.
- The image toolbar exposes technical OCR/vision mode controls permanently.
- Frontend modules are currently image-specific: `features/artifacts`, `features/multimodal-chat`, `features/vision-diagnostics`, and `features/image-evals`.

## Current attachment lifecycle

- Documents imported through `documents.import` are library-like records and are listed by `documents.list`.
- Images imported through `artifacts.import` are artifact records and are listed by `artifacts.list`.
- Chat can attach image artifact IDs to a user message.
- Chat cannot yet attach PDFs, TXT, or Markdown files directly as session-scoped attachments.
- There is no session/library scope column for documents or artifacts.
- There is no document-message link table.
- There is no promotion lifecycle from session attachment to persistent Source.

## Current OCR and vision path

- `ChatService.send` accepts `artifact_ids`, `multimodal_mode`, `vision_model`, and `analysis_request_id`.
- Image chat calls `VisionService.analyze` for the first attached image and links the artifacts to the user message.
- `VisionService.analyze` supports `ocr_only`, `vision_only`, and `combined`.
- OCR-only can return the observed canned OCR status sentence as the assistant answer.
- `ChatService.send` can use that analysis output directly as the assistant message without calling the selected final chat model.
- Default chat multimodal mode is currently `ocr_only`, not `automatic`.
- Combined mode does call OCR and a confirmed vision model when configured, but final answer synthesis is still local/canned rather than a model-generation stage.

## Current model capability path

- `ModelService.inspect` posts to Ollama `/api/show`.
- Vision capability is confirmed only when returned capabilities include `vision`.
- Name heuristics are not used to confirm vision support.
- Capability cache rows include text generation, vision, embedding, tools, context length, and error fields.
- Error results currently store capability states mostly as `unknown`, so UI truthfulness can be improved by distinguishing `error` or stale cache states.

## Current thumbnail-serving path

- Backend creates thumbnail derivative files and exposes `thumbnail_path` on artifact records.
- Frontend converts local thumbnail paths with `convertFileSrc`.
- The reported installed-app behavior shows backend image access works while frontend thumbnail rendering can fail, so packaged thumbnail access needs a secure read fallback or protocol fix.

## Current known failures to correct

- The product model is split into Documents and Images instead of one Sources library plus session attachments.
- Direct chat attachment only supports images; direct PDF/TXT/Markdown attachment is missing.
- Session attachments are not hidden from Sources because there is no session/library scope.
- OCR-only can stop at a canned status sentence instead of final model synthesis.
- The selected chat model and selected vision model are not clearly separated in final-message provenance.
- Automatic image mode is missing.
- The UI can imply a vision model is selected while the executed route is only OCR.
- Thumbnail rendering is broken in the installed app despite backend access working.
- Interactive RAG prompt still requires repeated retrieved-context boilerplate for normal answer styles.
- No installed-app validation has been rerun after this correction prompt.
